# perf-02 db-index

| 項目 | 値 |
| --- | --- |
| 分類 | `db-index` |
| 変更のコミット | `f4d14b0` |
| 変更ファイル | `webapp/sql-changes/01-db-index.sql` |
| 比較対象 | `baseline` |

## 変更内容

変更前は、対象のクエリがすべてテーブル全件スキャンだった。次の4本を追加した。

| インデックス | 対象のクエリ |
| --- | --- |
| `comments (post_id, created_at)` | 投稿ごとのコメント数、新しいコメントの取得 |
| `comments (user_id)` | ユーザーページのコメント数 |
| `posts (created_at)` | トップページと `/posts` の新着順 |
| `posts (user_id, created_at)` | ユーザーページの投稿一覧 |

`users` は1,000件と少なく、検索は主キーと `account_name` で足りるので追加していない。

## 結果

| 遅延 | 条件 | スコア | 成功 | 失敗 | 判定 |
| --- | --- | --- | --- | --- | --- |
| なし | 基準 | 4,355 / 4,478 / 4,478 | 4,204 / 4,317 / 4,329 | 0 / 0 / 0 | 完走 |
| なし | 変更後 | 28,116 / 29,762 / 15,574 | 26,200 / 27,713 / 14,639 | 0 / 0 / 0 | 完走 |
| 100ms | 基準 | 0 / 0 / 0 | 4 / 4 / 4 | 6 / 6 / 6 | 打ち切り |
| 100ms | 変更後 | 0 / 0 / 0 | 4 / 4 / 4 | 6 / 6 / 6 | 打ち切り |

## 評価

- 遅延なしでは、中央値が4,478から28,116へ6.3倍になった。失敗は0回のままである。
- 100msでは変化がなかった。インデックスはDB内の処理を速くするが、クエリの往復回数は減らさないためである。
- 変更後の3回目は15,574で、他の2回の約半分だった。基準ではほとんどばらつかなかったので、原因は未確認である。一番低い回でも基準の3.5倍である。

## 次の課題

100msで0点から抜け出すには、往復回数を減らす必要がある。候補は `db-query`（N+1の解消）と `app-connection`（プレースホルダ）である。
