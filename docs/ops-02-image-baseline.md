# 画像ファイルの基準データ

`perf-05` 以降の計測で、画像ファイルをどう初期状態へ戻しているかをまとめる。

メモリの改善ではない。計測の条件をそろえるための手順である。`perf-05` の改善そのもの（画像をnginxから配信する）とは別の話になる。

## 何が問題か

| 段階 | 画像の置き場所 | 計測前のリセット |
| --- | --- | --- |
| `perf-04` まで | DBの中 | DBを戻せば画像も戻る |
| `perf-05` から | DBの外のファイル | DBを戻しても、ファイルは戻らない |

`perf-05` では、ファイルがない画像は、最初の1回だけDBから読んでファイルを作る。1回目は遅く、2回目からは速い。

そのため、ファイルが揃っているかどうかで結果が変わる。

| 計測開始時の状態 | 結果 |
| --- | --- |
| ファイルがない | 最初の画像アクセスでDBを読むので遅い |
| 前回のファイルが残っている | 最初から速い |

これでは、改善で速くなったのか、前回のファイルが残っていただけなのかを区別できない。

## 解決方法

計測の前に、画像ファイルも毎回同じ状態へ戻す。

1. 全10,000枚の画像ファイルを一度だけ作り、基準データとして保存する。
2. 計測のたびに、画像置き場を空にして、基準データをコピーする。
3. 同じタイミングで、DBも基準データへ戻す。

これで毎回、画像10,000枚が揃い、ベンチで増えた分がない状態から始まる。

## データの場所

どちらもColimaのボリュームにあり、Gitには含まれない。

| ボリューム | 内容 |
| --- | --- |
| `private-isu_mysql_base` | DBの基準データ |
| `private-isu_images_base` | 画像ファイルの基準データ（10,000件、1.2GB） |
| `private-isu_images` | 計測中に使う画像ファイル |

## 操作

通常の計測は `scripts/practice.sh measure` が自動で戻すので、手作業は不要である。

基準データを作り直す場合だけ、次を実行する。`perf-05` 以降のコードを起動した状態で行う。

```bash
docker volume rm private-isu_images_base
scripts/practice.sh images
```
